# 会里使用许可

当前使用 **会里个人与内部使用许可 1.0**，正式文本见 [LICENSE](../LICENSE)。这是自定义的源码可用许可（source-available），不是 MIT 或 OSI 批准的开源许可。本页是便于阅读的说明，不替代正式文本。

## 可以做什么

- 个人免费学习、试用、运行、修改，用于自己的生活与工作。
- 公司、团队等组织免费在内部部署和修改，用于内部业务，包括商业工作；不用逐次征求作者同意。
- 让自己的 Agent 适配代码、授权的数据和存储，支付正常的 Agent 或基础设施费用。
- 将正常使用产生的会议纪要、报告等工作成果用于自己的工作；不能借此分发项目本身或实质复制的项目材料。
- 分享原仓库链接，介绍原项目，让其他人从原仓库取得材料后按适用许可自用。

## 未经书面授权不可以做什么

- 把源码、Skill 包、前端或修改版放到另一个下载站、网盘、群文件或公开仓库供人取得；免费分享、保留署名也不自动获得授权。
- 售卖、白标交付、打包出售，或把会里及其衍生功能作为对外产品、托管服务或付费部署包提供给第三方；免费试用不自动豁免。
- 包装成自己的项目向外宣传、推广或获客，抹去原作者及来源，或暗示原作者参与或背书。

“允许公司内部用”不等于允许向客户提供会里的软件功能。超出自用范围须事先取得相应权利人明确的书面授权，未回复不视为同意。

保留 `LICENSE`、`NOTICE`、原作者与原项目链接，以及第三方声明。你可以注明自己的改动，但不要把原作部分写成自己的独立原创。

## GitHub 的 fork 怎么处理

GitHub 公共仓库的服务条款允许用户在站内查看、使用、展示和 fork。保持仓库公开，就不能靠自定义许可取消这部分平台权利。因此“不允许对外分享”的条件存在这个明确例外；它不额外授权站外分发、售卖或冒充原创。[GitHub 服务条款 D.5](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service#5-license-grant-to-other-users)

## 为什么改称“源码公开”

本许可限制对外分发与商业再利用。通常的开源定义要求允许再分发和商业使用，所以此项目当前称为“源码公开 / source-available”。[OSI 开源定义](https://opensource.org/osd)
