# 隐私与分发边界

## 这个公开副本怎样整理

重新建立独立目录，以源码白名单取出前端、通用协议和连接器，再建立全新 Git 历史。没有复制原仓库历史或按目录整包上传。

排除个人画像、姓名与别名、原角色预设、真实业务分类、真实会议/聊天/项目/联系人、完整逐字稿、原应用/租户/实例标识、内部链接、私有路径、配对邀请、令牌、数据库、运行队列、日志、自动化配置、旧截图、录音和安装包。默认业务分类已移除；示例从空白重新编写。

引用资料用于理解功能，原文与内部地址没有纳入公开内容。示例截图来自本仓库的虚构数据模式。发布说明与海报不使用真实业务数量或人员信息。

## 使用者自己的资料

请把配置放在自己私有的数据目录，仓库中的 `profile.example.json` 默认没有身份和角色。API 密钥留在服务端或本机受限配置；不能写入前端变量、浏览器持久存储、MCP 参数或模型提示词。

连接器保存配置时使用受限目录权限与原子写入；它阻止账号漂移和携带凭据的 HTTP 重定向。多人服务还需后端认证与逐对象权限校验，这些不能靠连接器代替。

## 再次公开前

运行 `npm run check:privacy`。扫描器报告文件名/行号/规则，不回显命中的秘密。可另用私有术语文件补充作者姓名、内部域名与敏感项目名称：

```bash
python3 scripts/privacy_scan.py --terms-file /private/path/terms.txt
```

术语文件本身不能放入仓库。自动扫描无法证明所有内容都安全，仍应人工核对示例、图片、文档语义、提交历史和发布资产。发现泄露时应先撤销真实凭据，再移除内容并按平台流程处理历史缓存。
