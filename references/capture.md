# 随手记与背景交接

默认先记录。保存内容与 `clientRequestId`，未得到成功回执前冻结该请求内容；超时重试同一请求，不能换 ID 再发。草稿按认证用户隔离；未认证时禁用真实草稿保存。前端草稿不代表服务端已保存。

已保存记录支持搜索、完成和撤销。完成只影响本人这条随手记，不能改变会议中的他人行动。服务端检查归属，并用条件更新避免完成与交接同时发生。

用户明确“交给 Agent”后：

1. 按行动 ID 找已存在的交接任务，存在就返回原链接；不能重复创建。
2. 如宿主支持可回复的持久任务，创建一个并尽早保存真实任务 ID/链接；否则保持当前对话接手，并明确没有新任务链接。
3. 第一轮先在授权范围读取相关会议、聊天、文档和历史工作结果，给出带日期、来源和冲突说明的背景；询问真正缺少的信息。
4. 初步整理结束记为待本人补充，不等于这件事已完成。之后遵循本人回复继续执行并回读成果。
5. 进程超时或回写失败时，先检查已保存任务标识与当前状态；若创建结果不明，呈现待核对，不重复启动新任务。

参考前端使用 `mode: record | agent`、`agentFollowup` 与 HTTPS 结果链接。旧环境中的宿主专用字段需在适配器中转换，不把某家任务 URI 当跨 Agent 通用协议。
